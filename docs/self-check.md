# Self-check and CI

`yarn self-check` (`scripts/self-check.mjs`) reproduces the bounty eligibility gate ([bounty-rules.md](bounty-rules.md), Part A) as a list of named requirements. CI ([`.github/workflows/ci.yml`](../.github/workflows/ci.yml)) runs the same script, so a green local run and a green CI run mean the same thing. The script has no dependencies: on a fresh clone run `node scripts/self-check.mjs`, because Yarn refuses `yarn self-check` until the first install, and the clean install is itself a requirement. Delivered by issue **#14**; reused by **#19** (release/fresh-scaffold validation).

`yarn check` stays the fast inner loop (lint + types + test). It also ships in projects generated by the CLI, which no longer contain `template.json`.

## Requirements

| Id | Gate | What fails it |
|---|---|---|
| `toolchain` | GATE-08 | Node.js older than `engines.node`, or no Yarn (`scripts/doctor.mjs`) |
| `manifest` | GATE-09 | `template.json` missing or invalid for create-scaffold-hbar (`scripts/validate-template.mjs`) |
| `docs` | GATE-10/11 | `README.md` or `AGENTS.md` missing/empty, or either cites a `yarn <script>` that is not a root script (lines starting with `Planned`/`Planejados` are exempt) |
| `license` | GATE-03 | `LICENSE` missing or not MIT |
| `no-env` | GATE-19 | A `.env*` file other than `.env.example` is tracked or not ignored, or `.gitignore` does not ignore `.env` |
| `secrets` | GATE-19 | `yarn secrets:scan` (gitleaks, rules: defaults + [`.gitleaks.toml`](../.gitleaks.toml)) finds a leak in the git history or working tree, or a Hedera DER private key / raw `*_KEY=<64 hex>` / PEM key is in the working tree |
| `install` | GATE-15 | `yarn install --immutable` fails (lockfile out of date) |
| `lint` | GATE-16 | `yarn lint` |
| `types` | — | `yarn check-types` |
| `tests` | — | `yarn test` (whatever the test suite of #13 contains) |
| `build` | GATE-17 | `yarn build` |
| `boot` | GATE-18 | `yarn serve` does not answer within 90 s, or `/`, `/dashboard` or `/api/env/status` does not return 200 (the API must also return JSON) |

Requirements that depend on a failed one (`lint`, `types`, `tests`, `build` on `install`; `boot` on `build`) are reported as `BLOCKED`, not run. All other requirements always run, so one execution lists every failure.

## Output

Each requirement prints `PASS`, `FAIL`, `SKIP` or `BLOCKED` with its id and gate reference. A failure prints the last 40 lines of the command output, then the exact cause (file and line for docs, `.env` and secrets findings) and a fix hint. The summary repeats every failure. Exit code: `0` all passed, `1` at least one failed, `2` unknown requirement id in an option.

On GitHub Actions the full output of a failed step is in a collapsible group, each failure is an `::error` annotation, and the job summary has a table of all requirements.

```bash
yarn self-check                         # everything
yarn self-check --only secrets,no-env   # a subset
yarn self-check --skip boot             # everything but one
yarn self-check --list                  # ids, gate references and descriptions
```

In a project generated by the CLI run `yarn self-check --skip manifest`: the CLI consumes and deletes `template.json`.

## Secret scanning

The step runs `yarn secrets:scan` ([`scripts/secret-scan.mjs`](../scripts/secret-scan.mjs)), the project's single secret-scan implementation: gitleaks over every ref of the git history (merge commits included) and the non-ignored working tree, with the default rules plus the Hedera rules in [`.gitleaks.toml`](../.gitleaks.toml) (DER-encoded ED25519/ECDSA keys, raw hex keys assigned to key-like names, mnemonics). Matched values are always redacted and allowlists stay narrow; see [docs/security.md](security.md) (Secret scanning). The built-in patterns also scan the working tree, which catches a key before it is committed.

Locally, without gitleaks on `PATH`, only the built-in patterns run and the step prints a warning (`brew install gitleaks`). In CI a missing gitleaks fails the step.

## CI

The workflow runs on every push and pull request, on Node 20.18.3 (the gate's minimum) and 24. The environment is clean by construction: a fresh runner, `actions/setup-node` without dependency cache, no build cache, no `.env` and no secrets. The job calls `node scripts/self-check.mjs` and `yarn install --immutable` runs inside it, as the `install` requirement. gitleaks is downloaded at a pinned version and its SHA-256 is verified; the checkout fetches the full history so that gitleaks sees every commit.
