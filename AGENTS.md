# Agent Guide

## Architecture
`packages/hardhat` owns Solidity/deploy/test; `packages/nextjs` is the developer console; `packages/sdk` owns Hedera, oracle and Mirror Node adapters and the network configuration. Credentials (the current direction): HCS records issuer-signed evidence, `CredentialRegistry` decides status, Mirror Node audits. The settlement modules (oracle, HTS) are history from the previous direction. Onboarding: [docs/quick-start.md](docs/quick-start.md); what each Hedera service does: [docs/hedera.md](docs/hedera.md); real errors: [docs/troubleshooting.md](docs/troubleshooting.md).

## Rules
- Never commit secrets, private keys, mnemonics or real account credentials.
- Add contracts with unit tests, deployment and typed frontend artifacts.
- HCS publications must persist transaction ID and HashScan URL.
- HTS operations must be idempotent and validate token/account associations.
- Mirror Node reads are eventual-consistency aware.
- Settlement identity, idempotency and replay rules are normative in `docs/architecture.md` (ADR-001). Never use a payload hash, a signature or a nonce as the idempotency key: it is `eventKey` (ADR §4.3).
- `externalEventId` must be a pure, deterministic function of the event's identifying fields only (ADR §4.4, R1–R6). Never hash JSON.
- HCS is evidence, not validity. The contract cannot read HCS; never present `HcsRef` as verified on-chain.
- Publish to HCS and capture the consensus receipt **before** releasing an attestation for settlement (ADR D11).
- Every HTS response code must be checked (`SUCCESS = 22`); any other value reverts the whole settlement.
- No role may settle, mint or alter a processed record (ADR D12).
- Hedera environment validation has one source: `validateHederaEnvironment` in `@sh/sdk`. The dashboard, CI and scripts import it; never re-implement it. It must never put a private key, or a URL beyond its origin, in a message, log or result.
- HCS evidence has one implementation: `packages/sdk/hedera/hcs` (envelope, identifiers, encode/decode, publisher). #10, #12 and the oracle import it; never write a second parser, JSON variant or identifier formula. The message is `0x01 || abi.encode(SettlementEvent) || signature` ([docs/hcs-envelope.md](docs/hcs-envelope.md)). The publisher never retries by itself: retries after an `unknown` outcome are the caller's policy.
- The oracle has one interface: `packages/sdk/hedera/oracle` (`OracleProvider`/`EventNormalizer`/`Attestor`, composed by `createOracleAdapter`). The mock (`createMockOracleAdapter`) is for tests, CI and local dev only — deterministic, no credentials, always labelled `mock` in `eventSource`. Real oracle integration for production/demo is issue #23; selecting it is by `ORACLE_PROVIDER` configuration, never a conditional in consumer code. See [docs/oracle-adapter.md](docs/oracle-adapter.md).
- HTS has one integration layer: `packages/sdk/hedera/hts` (settlement plan, preconditions, association, errors, idempotency). Nothing else calls the Hedera Token Service. The settled asset is an HTS token, never a generic ERC-20. Production custody is the `SettlementRouter` (it mints and transfers on-chain and is the single enforcement point of replay protection); the adapter is its off-chain counterpart, and off-chain execution (`HEDERA_HTS_CUSTODY=operator`) is for development and Testnet only, refused on mainnet. The idempotency key is `eventKey`. See [docs/hts-adapter.md](docs/hts-adapter.md).
- Credential privacy and trust are normative in ADR-002 ([docs/architecture.md](docs/architecture.md#adr-002--credentials-privacy-on-chain-vs-off-chain-and-data-model), #39), the source of truth for `CredentialRegistry` roles and its privacy boundary. Personal data (holder name, e-mail, CPF, any `idValue`, the salt, the document) never goes to calldata, logs, HCS, Mirror queries, server logs or browser storage; only identifiers, hashes, commitments, status and timestamps are public. The admin never issues or alters a record. Every issuance pins `submitter` to the account that sends it, never `address(0)` (CD6). Expiry lives in `credentialHash` (v1); a v2 struct is a new ADR decision, never a silent change of v1 (CD5). Claims are integrity-protected, not hidden (CD4).
- The credential data model and identity rules are normative in [docs/credential-schema.md](docs/credential-schema.md) (#38, data-model part of ADR-002). They have one implementation, `packages/sdk/hedera/credentials/schema.ts` (`deriveCredential`, `computeSchemaId`, `computeExternalCredentialId`, `computeSubjectCommitment`, `computeCredentialHash`). Never re-derive these values elsewhere. `externalCredentialId` follows C1–C6: only `schemaId` and the issuer's `reference`, never personal data or volatile fields. `credentialHash` is ABI-encoded typed content, never JSON. `issuedAt`/`expiresAt` are committed in `credentialHash` and are not `signedAt`/`validUntil`. `subjectCommitment` always uses a unique per-credential salt.
- The JSON holder document is the whole credential: the template has no visual document (PDF/image) and no document storage (ADR-004, #26). A certificate is rendered from the verified document. A fork that adds a file uses a `bytes32 documentHash` claim in a new schema version, never publishes that hash on its own, and stores the file only encrypted to the holder, never on public IPFS or a public URL.
- `CredentialRegistry` is the source of truth for credential status (`statusOf(credentialId)`). The idempotency key is `credentialId` (issuer namespace + `externalCredentialId`). Authenticity is checked before uniqueness, and no role may issue or alter the hash/subject of an existing record. See [docs/credential-registry.md](docs/credential-registry.md).
- Credential audit has one implementation: `packages/sdk/hedera/audit` (`auditCredential`/`auditHcsMessage`). The public verifier, the issuer console (#12) and the testnet validation (#18) consume its report; never re-implement correlation or Mirror polling. The report never overrides `statusOf`, and absent Mirror data is `pending` inside the index budget, never "missing". Credential HCS messages are parsed only by `packages/sdk/hedera/hcs/credential-envelope.ts`. See [docs/credential-audit.md](docs/credential-audit.md).
- Credential issuance and revocation have one implementation: `packages/sdk/hedera/credentials` (issuer form presets, EIP-712 payloads, registry calldata over the generated ABI, `IssuerError` taxonomy, `runIssuance`/`runRevocation`, server handlers). Identifiers and hashes come only from `schema.ts` (`deriveCredential`/`toCredentialEvent`); the issuer console (`/issuer`) only renders the flow and never derives a value in a page. Raw holder identifiers never leave the browser and are never stored. Every issuance pins `submitter` to the account that sends `issue` (never `address(0)`: the signed event is public on HCS before `issue`, so an unpinned event can be front-run with a forged `HcsRef`, docs/security.md T-5/F-1); the server refuses to publish an unpinned issuance. The server publishes to HCS with the operator only for the namespace's current active signer, and the registry transaction is sent after the consensus receipt. #41 extends this module. See [docs/issuer-console.md](docs/issuer-console.md).
- The Testnet validation (#18) has one implementation: `packages/sdk/hedera/testnet` (`planVerification`/`runVerification`, report), run by `yarn verify:testnet`. It composes `validateHederaEnvironment`, the generated manifest, `runIssuance`/`runRevocation` with the console's server handlers and `auditCredential`; never re-implement any of them there. Testnet only. Evidence under `docs/evidence/testnet/` comes from real runs only: never hand-write or edit it. See [docs/testnet-validation.md](docs/testnet-validation.md).
- Infrastructure health has one implementation: `checkHederaHealth` in `packages/sdk/hedera/health.ts`, which composes `validateHederaEnvironment`, `verifyHcsTopic` and the registry reader. `/dashboard` and `GET /api/env/status` render it; never add a check in the page. Client components import client-safe subpaths only (`@sh/sdk/hedera/wallet`, `@sh/sdk/hedera/contracts`, `@sh/sdk/hedera/audit/registry`, `@sh/sdk/hedera/networks`), never the package root. See [docs/dashboard.md](docs/dashboard.md).
- ABIs and contract addresses are never written by hand: `packages/sdk/generated/` is the output of `packages/hardhat/scripts/generateTsAbis.ts` (run by `yarn deploy` and `yarn codegen`), committed, and never edited. Consumers resolve contracts with `getDeployedContract` from `@sh/sdk/hedera/contracts` (an explicitly configured address wins over the manifest); React code uses `useDeployedContract`/domain hooks such as `useCredentialRegistry` in `packages/nextjs/hooks`, never a contract instance built from a literal address. After changing a contract run `yarn codegen` (CI fails on stale output). See [docs/integration.md](docs/integration.md#contract-abi-and-address-codegen).
- External integrations use an interface, timeout, validation and deterministic test fixture.
- Security baseline, threat model, trust boundaries, prohibited practices and the security Definition of Done live in [docs/security.md](docs/security.md). Input from forms, wallets, query strings and external APIs is untrusted until a boundary check (on-chain for validity) accepts it. Secret scanning has one implementation: `.gitleaks.toml` run by `scripts/secret-scan.mjs` (full history and working tree); never silence a finding without a narrow, documented allowlist entry, and never print a matched value.
- The Hedera Harness recipe in `.harness/` (`spec.yaml`, `validators/static.json`, `validators/yarn.json`, `prd.md`) is the template's deterministic validation (Tier 0–1) and ships into every scaffolded project; it is submitted with the repository (bounty GATE-20). When you add a root script, a single-source module or a normative rule, update the validators in the same change; never assert `template.json` there (the CLI deletes it). Tiers 2, 3 and 3.5 are deliberately off. See [docs/harness.md](docs/harness.md) and ADR-003.
- Shared test fixtures have one implementation: `@sh/sdk/testing` (credentials, in-memory HCS topic, fake Mirror Node/relay, health scenarios). Tests in every package reuse it; runtime code never imports it. `yarn test` must stay offline and credential-free; live Testnet tests are opt-in `*.integration.test.ts`. Layers, fixtures and coverage targets are in [docs/testing.md](docs/testing.md).

## Commands
Available: `yarn doctor`, `yarn setup` (validates network, account and balance; exit 0 valid, 1 invalid, 2 network unreachable; `--json` for machines), `yarn hcs:topic` (creates the HCS evidence topic once: shows the plan and cost and asks before paying; `--yes` skips the question; never a second topic over a usable configured one; refuses mainnet without `--allow-mainnet`; `--smoke-test` publishes and reads back one message), `yarn hts:token` (creates a development settlement token: operator as treasury/supply key; never a second one over a usable configured token; refuses mainnet without `--allow-mainnet`), `yarn hts:settle <preflight|associate|transfer>` (manual HTS testing: shows the plan and cost and asks before sending; `transfer` only executes under operator custody; refuses mainnet without `--allow-mainnet`), `yarn deploy --network <hederaTestnet|hederaLocal>` (deploys, then regenerates `packages/sdk/generated` with this network's addresses and contract ids; needs `__RUNTIME_DEPLOYER_PRIVATE_KEY`), `yarn codegen` (regenerates ABIs/error table from the compiled contracts, no network; `--network <name>` also re-reads that network's deployment files), `yarn verify:testnet` (end-to-end credential validation on the real Testnet: preflight, issue with the HCS receipt first, audit until consistent, deliberate re-issuance attempts, revoke, audit again; shows the plan and cost and asks before paying; `--yes` skips the question, `--dry-run` only checks; refuses mainnet; writes the evidence to `docs/evidence/testnet/`), `yarn dev` (`yarn start` is the same dev server; `yarn serve` is production), `yarn build`, `yarn lint`, `yarn check-types`, `yarn test`, `yarn check` (lint + types + test + `harness:doctor`; the fast inner loop), `yarn coverage` (tests with coverage; fails below the targets in docs/testing.md), `yarn self-check` (the eligibility gate: manifest, docs, license, no `.env`, secrets via `yarn secrets:scan`, install, lint, types, tests, build, boot + core routes; names the failing requirement; `--only`/`--skip <id,...>`, `--list`; this is what CI runs; before the first install call it as `node scripts/self-check.mjs`, see [docs/self-check.md](docs/self-check.md)), `yarn format`, `yarn harness:doctor` (loads the harness recipe; fails on a schema error), `yarn harness:validate` (full harness Tier 0–1: static invariants, secret scan, install, lint, types, tests, build; refuses a workspace with a `.env`, so run it in a clean clone), `yarn secrets:scan` (gitleaks over every ref of the git history, merge commits included, and the non-ignored working tree; values always redacted; exit 0 clean, 1 findings, 2 could not run, e.g. gitleaks missing or shallow clone; `--history`, `--tree`, `--self-test`), `yarn test:e2e` (#15: Playwright, `packages/nextjs/e2e`; browser-level route smoke tests and the public verifier's lifecycle against a mocked `CredentialRegistry`/Mirror Node response at the HTTP boundary — no live Hedera network or credentials; needs `playwright install chromium` once; **not** part of `yarn check` or CI — see `docs/scaffold-compat.md` §6.2 for why). Per-package scripts are `hardhat:*`, `next:*` and `sdk:*`.
Planned: `yarn test:integration`.

Structure rules (see `docs/scaffold-compat.md`): workspaces are named `@sh/hardhat`, `@sh/nextjs`, `@sh/sdk` and the CLI depends on that naming. `@sh/sdk` is consumed as TypeScript source. Chain ids and RPC/Mirror/HashScan URLs live only in `packages/sdk/hedera/networks.ts`. One `.env` at the repository root; secrets never use the `NEXT_PUBLIC_` prefix. `.env.example` is generated from `template.json` (`envVars`) by the CLI; keep them equal (`node scripts/validate-template.mjs`). Run commands with the `--` form: `npm create scaffold-hbar@latest -- --template <owner>/<repo>`.

## Definition of Done
Tests, lint/typecheck/format, error handling, docs, no secrets (`yarn secrets:scan` exits 0), HashScan evidence for testnet changes, and every applicable item of the security Definition of Done in [docs/security.md](docs/security.md#9-security-definition-of-done-every-pull-request).
